# 飞牛 fnOS 桌面客户端（Windows 11）需求分析 v0.1

> 状态：待审核 ｜ 作者：Hermes（需求分析）｜ 审核人：老大
> 定位：**自用版**、源码**公开可审计**、Tauri 2 技术栈

---

## 1. 项目背景与目标

### 1.1 背景
- 社区第三方 fnOS 桌面客户端（Electron）功能不错，但**闭源 + 不可审计**，存在后门/凭据外传风险，不可信任
- 社区有真实需求（原文章评论区大量求客户端），自研后可开源回馈
- 本人技术栈（Node/Python）与安全敏感诉求决定了技术选型方向

### 1.2 目标
- 在 **Windows 11** 上安装运行的 fnOS 桌面客户端（v1 自用）
- **信任链自持**：源码公开 → CI 可复现构建 → 更新签名校验，全程可审计
- 发布到 GitHub（jonas-yu，公开仓库）

### 1.3 非目标（v1 明确不做）
- FN ID 远程访问（用户不用，砍掉）
- 原生 API 深度对接（下载进度条、相册、影视等，进 v2）
- 代码签名证书（SmartScreen 弹窗接受"仍要运行"）
- macOS / Linux 版本

## 3. 技术方案

### 3.1 总体架构

```
┌────────────────────────── 客户端（Windows 11）──────────────────────────┐
│                                                                        │
│  Tauri 2 Shell（Rust 后端）                                              │
│  ├─ 窗口管理：主窗口 / 多应用窗口 / 锁屏窗口                              │
│  ├─ 系统托盘 + 全局快捷键（tauri-plugin-global-shortcut）                │
│  ├─ 服务器 Profile 管理（增删改、默认连接、状态记忆）                      │
│  ├─ 启动密码：argon2 哈希校验 + 忘密重置                                  │
│  └─ 自动更新（tauri-plugin-updater，更新源 = GitHub Releases）           │
│                                                                        │
│  WebView2（每台 NAS 一个独立数据分区 data_directory）                     │
│  ├─ Profile A → https://192.168.x.x:5667（局域网 IP）                    │
│  ├─ Profile B → https://aipoly.iepose.cn（自有域名）                     │
│  └─ 登录态天然隔离持久化（不接触 session token 本身）                     │
└────────────────────────────────────────────────────────────────────────┘
            │ WebSocket 协议（对齐 trim-cli 连接约定）
            ▼
   ┌────────────────── fnOS NAS ──────────────────┐
   │  网页端 SPA（被 WebView2 加载）                  │
   │  ws://5666 / wss://5667 / wss:443（scheme 自适应）│
   └──────────────────────────────────────────────┘
```

### 3.2 关键设计点

| 设计点 | 方案 | 依据 |
|---|---|---|
| 连接协议 | 对齐 trim-cli 的 connection 约定：本机 `ws://5666`、远程 IP `wss://5667`、域名 `wss:443`、scheme 自适应 | 本技能库 trim-cli（FNOS skill）已有完整协议文档 |
| 多服务器登录态隔离 | 每台 NAS 一个 **WebView2 独立数据分区**（Tauri 2 `data_directory`），登录态各自持久化、互不干扰 | 对齐 trim-cli 的 `--profile` 会话隔离思路 |
| 凭据策略 | 客户端**零凭据逻辑**：NAS 账号密码只在网页登录框输入；session 过期则重新网页登录 | 决策⑤ A 方案 |
| 启动密码 | argon2 哈希存本地配置；忘记密码 → 重置 = 清空所有 Profile 登录态分区 | 决策⑤ |
| 自签证书 | WebView2 默认拦截自签证书；连接设置中提供"信任该 NAS 证书"（仅对当前 Profile 生效）或引导安装证书 | 风险对策，开发期真机验证 |
| 前端（客户端自身 UI） | Vue3 + Vite（登录壳/服务器管理/设置/锁屏，共约 4 个页面，轻量） | 实现建议，可改 |

## 4. 功能需求

### 4.1 v1 功能（P0 + P1）

#### P0 必须有

| 功能 | 需求描述 | 验收标准 |
|---|---|---|
| 独立窗口 | 客户端以独立桌面应用运行，不依赖浏览器 | 双击启动即进入 fnOS 界面 |
| 多服务器独立登录态 | 支持添加多台 NAS（局域网 IP / 域名），各自独立登录、互不影响 | 切换 Profile 后登录态互不串扰，重启后仍保持 |
| IP/域名连接 | 支持 `IP[:端口]`、`域名[:端口]` 两种地址输入；剪贴板可直接粘贴地址 | 局域网 IP 与自有域名均可正常打开 fnOS 界面 |
| 多窗口多任务 | 从 fnOS 主页打开的每个应用在独立窗口运行 | 多个应用窗口可并行，互不干扰 |
| 系统托盘常驻 | 关闭窗口最小化到托盘，不退出程序 | 关窗后托盘图标存在，点击可恢复 |
| 剪贴板粘贴 | 服务器地址输入框支持粘贴 IP/域名 | 粘贴即识别 |
| 视图缩放 | 支持缩放网页视图，不受系统缩放率影响 | 200% 系统缩放下可独立调节 |

#### P1 要有

| 功能 | 需求描述 | 验收标准 |
|---|---|---|
| 启动密码 + 一键锁定 | 可设置启动密码；离开时一键锁定，锁屏窗口需密码恢复 | 锁定后无密码不可查看/操作；锁屏视觉统一 |
| 全局快捷键 | 锁定、隐藏等操作可自定义快捷键（系统级生效） | 在任意应用前台可触发锁定/隐藏 |
| 深色玻璃 UI（跟随系统） | 登录壳/服务器管理/设置/锁屏界面统一深色玻璃质感，跟随系统深浅色 | 深浅色切换正常，风格统一 |

### 4.2 v2 功能（P2 暂缓，仅记录方向）

| 功能 | 说明 | 参考 |
|---|---|---|
| 老板键全隐藏 | 连托盘图标一起隐藏，快捷键呼出 | 锦上添花 |
| 原生下载进度条 | 不走网页，直连下载 API 展示进度 | trim-cli download 模块 |
| 系统通知 | 下载完成/任务变更推送 | trim-cli download 模块 |
| 相册/影视/文件原生增强 | 原生浏览与操作 | trim-cli photos / media / file 模块 |
| FN ID（如未来需要） | 需实测逆向隧道协议 | 风险最高，非必要不做 |

## 5. 非功能需求

| 维度 | 要求 |
|---|---|
| 安全 | 凭据零落盘；启动密码 argon2；更新包签名校验；依赖可审计（cargo.lock 锁定） |
| 体积/资源 | 安装包 ≤ 15MB；空闲内存占用尽量低（对比 Electron 明显优势） |
| 兼容性 | Windows 11 x64；依赖系统 WebView2 运行时（Win11 自带） |
| 可维护性 | 源码公开、CI 自动构建、Release 自动更新源 |
| 易用性 | 首次添加 NAS 三步内完成；锁屏/解锁零学习成本 |

## 6. 信任链与安全设计（本项目核心卖点）

```
公开源码（可审计）
   → CI 可复现构建（GitHub Actions 官方 windows-latest runner）
   → 构建产物上传 Release（哈希可核对）
   → 自动更新包 RSA 签名校验（私钥只存 Actions secrets，不入库）
   → 客户端只存登录态，不存 NAS 账号密码
```

安全红线：
1. **NAS 账号密码永不落盘**（只在网页登录框输入）
2. **更新签名私钥永不进仓库**（GitHub Actions secrets 管理，支持轮换）
3. **依赖锁定**（cargo.lock），依赖变更需走 PR 可审查
4. 构建产物由 CI 生成，本地不手工出包（防污染）

## 7. 工程与交付

### 7.1 仓库
- 建议命名：`jonas-yu/fnos-desktop`（公开）
- 目录结构：`src/`（Rust）、`ui/`（Vue3 壳）、`docs/`、`tauri.conf.json`、GitHub Actions workflow

### 7.2 CI 流水线（GitHub Actions）
```
push → windows-latest runner
  → tauri-action（编译 Rust + 前端）
  → 产出 NSIS 安装包 + 绿色便携版
  → 发布 GitHub Release（tag v*）
  → 自动更新源生效（客户端下次启动检查）
```

### 7.3 里程碑

| 阶段 | 内容 | 出口标准 |
|---|---|---|
| M1 骨架 | Tauri 初始化、主窗口加载 fnOS、托盘、单实例 | 能打开 fnOS 网页 |
| M2 连接与 Profile | 多 NAS Profile、独立数据分区、地址粘贴、视图缩放 | 双 NAS 登录态隔离验证通过 |
| M3 锁屏与体验 | 启动密码/锁定/快捷键/深色 UI | 安全功能全绿 |
| M4 CI 与更新 | Actions 出包、Release、Updater 签名链路 | 更新链路端到端验证 |
| M5 发布 | v0.1.0 发布 + README/使用文档 | 安装包可下载安装 |

### 7.4 开发协作方式
- 代码由 Hermes 编写（可分批交付），老大在 Win11 真机验证（用户偏好：给操作指引自己动手）
- 真机验证参考 trim-cli skill 的 device-validation 流程
- 重大交付前可开子代理独立复审（用户既有偏好）

## 8. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| WebView2 拦截自签证书（局域网 IP 连接时） | 中 | Profile 级"信任该 NAS 证书"；或引导安装证书；开发期真机验证 |
| fnOS 网页端改版导致兼容性问题 | 中 | 客户端壳与网页解耦；必要时 v2 原生 API 兜底 |
| SmartScreen"未知发布者"弹窗 | 低 | 文档说明"更多信息→仍要运行"；v2 再评估签名证书 |
| 更新密钥泄露 | 低 | 私钥只存 Actions secrets，支持轮换，泄露可吊销重签 |
| Rust 工具链陌生 | 低 | CI 构建，本地无需装；Hermes 出代码 |
